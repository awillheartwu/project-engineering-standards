# 版本收尾与交付检查

版本收尾是 active 项目从“日常开发”进入“可交付状态”的检查点。只有用户明确要求当前版本进入版本收尾，才启动测试和交付准备；讨论、计划或提到“收尾”都不算启动授权。

## 0. 先确认交付类型

| 类型 | 主要产物 | 真实验收对象 |
| --- | --- | --- |
| 服务器/常驻服务 | 镜像或可运行包、部署配置 | 目标环境中的运行版本、健康检查、关键行为、回滚 |
| Windows/macOS 桌面应用 | 安装包、升级包 | 目标操作系统上的安装、升级、启动、数据恢复 |
| 平台插件 | 插件包或 Git 归档 | 干净实例安装、配置、真实平台行为、重载 |
| 静态页面 | 构建目录或静态包 | 实际访问、缓存、版本和资源完整性 |
| 本地工具/脚本 | 可执行文件或源码入口 | 一条命令运行、样本数据、失败路径 |

交付类型在定位卡里已经确定。版本收尾时只确认，不在此时扩大范围。

## 1. 冻结范围

- 记录目标版本、分支、需求范围、已知缺陷和明确延期项。
- 保留工作区中与本次版本无关的修改；只暂存本次范围。
- 检查远端分叉；有他人提交时先合并审阅，不强推覆盖。
- 冻结后新增需求默认进入下一版本，除非用户明确改变范围。

## 2. 数据与配置

- 列出本次涉及的数据库迁移、配置变更、文件格式变化和用户数据处理。
- 数据面 D1/D2 在迁移前生成备份，并验证备份可读取、可恢复。
- 预览迁移影响；准备回退路径。失败时保留现场，不自动回滚数据库。
- 真实配置和密钥留在仓库外；测试使用临时数据，不连接生产环境。
- 没有数据变更时，也要在报告中明确写“无数据变更”，不要省略。

## 3. 测试整理

按 references/testing.md 执行。收尾阶段只做三件事：盘点并删除无效测试；为本次版本和已确认缺陷补最小行为覆盖；先跑目标测试、再跑完整检查。不追覆盖率，不为文案、样式、组件结构或实现细节新增测试。

## 4. 运行检查

- 使用项目约定的完整检查命令；日常检查不能替代收尾检查。
- 本地通过、CI 通过、构建成功、部署成功、真实环境验收是不同层，分别记录。
- 在干净环境构建交付物；记录版本号、提交 SHA、镜像 digest 或安装包校验值。
- 中途改代码后，只重跑受影响项；不要重复无效的整套检查。
- 如果检查不可用，报告缺失依赖、未覆盖范围和剩余的验证边界。

## 5. 文档与版本

- 按 references/documentation.md 做文档盘点：保留、合并、删除或归档；检查命令和链接是否仍可用。
- 更新使用说明、开发说明、配置示例和当前限制；删除已完成或失效的临时计划。
- 版本号只保留一个事实来源；标签、镜像、安装包和界面版本应能对应。
- 变更记录写用户可理解的行为变化，不把提交历史复制一遍。
- 文档只维护一份；同一规则不要同时写在 README、AGENTS 和多个指南里。

## 6. 构建与验收

| 类型 | 最低构建检查 | 最低验收 |
| --- | --- | --- |
| 服务器/常驻服务 | 镜像/包可重复构建；配置可解析 | 部署到目标环境；版本、健康、关键只读行为正确；回滚路径可用 |
| 桌面应用 | 安装包/升级包在干净环境构建 | 目标系统安装、启动、升级、数据恢复；WSL/CI 不能替代 |
| 平台插件 | 干净归档可导入；包体积和排除项正确 | 干净实例安装、配置、真实平台行为和重载 |
| 静态页面 | 生产构建成功；资源路径正确 | 实际 HTTP 访问、缓存和版本正确 |
| 本地工具 | 一条命令可运行；依赖锁定 | 样本数据、错误路径和重复运行 |

验收不通过时，不把“构建成功”写成“交付完成”。如果只能在受限环境验证，明确写出未验证的层。

## 7. 发布、部署与分发

- 提交、推送、打标签、部署、发布、分发分别按用户授权执行；版本收尾不自动授予这些动作。
- 发布标签指向最终 main 提交；标签创建后不移动。首次发布和后续发布都要核对提交。
- 部署使用已经验收的产物；不要在部署时重新构建一个不同版本。
- 分发前核对文件名、版本、校验值、可见性和访问权限；首公开发布可能需要单独确认。
- 部署后核对运行版本/SHA 和健康状态；发布后核对实际可下载产物。
- 一个远端成功、另一个失败时，只补失败端，不重复已完成的外部动作。

## 8. 交付报告

       版本：
       范围：
       本地检查：
       CI：
       构建产物/校验值：
       部署或分发：
       真实环境验收：
       未验证或阻塞：
       回滚方式：

报告要区分“已通过”“未运行”“无法验证”。不能把未运行的测试写成通过，也不能把部署成功写成业务验收完成。

## 9. 停止条件

出现以下情况时停止交付并报告，不要继续推进：

- 没有备份就执行不可逆迁移。
- 测试或验收使用真实用户数据，且没有授权和隔离。
- 工作区有未审阅的无关改动，无法保证提交范围。
- 远端存在未知分叉，准备强推或覆盖他人提交。
- 缺少交付所需的密钥、签名、权限或目标环境。
- 构建产物与验收产物不一致。
- 用户没有授权提交、推送、部署、发布或分发。
