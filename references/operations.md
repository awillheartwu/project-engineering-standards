# 运行、安全与恢复

适用于常驻服务、NAS 应用、桌面分发和需要保留数据的项目。安全、备份、事故和监控按定位卡的责任面、运行面和数据面裁剪；一次性脚本不套完整流程。

## 安全边界

- 先标注暴露面：仅本机、局域网、公网。公网服务必须有 TLS、认证、限流和明确的访问入口。
- 管理面板、队列 UI、数据库管理页默认不公开；确需公开时单独评估认证、网络白名单和审计。
- 密钥放仓库外，按项目和环境隔离；只给需要的步骤，不把生产密钥注入测试和构建 job。
- 密钥不进日志、截图、错误响应、镜像层或命令历史；轮换时记录旧密钥的失效时间。
- 自托管 runner 挂载 Docker socket 等于宿主 root：只运行受信任代码，禁止 fork PR 默认执行，Actions 固定版本。
- 日志和报告最小化个人信息：群号、昵称、截图路径、Token、Cookie 和完整文件路径按需要脱敏。
- 依赖、基础镜像、模型权重、字体和素材都要有许可证来源；不清楚许可的分发物不进入公开发布。

## 提交与推送前的隐私检查

这部分适用于所有项目，包括仅本地使用或私有仓库。准备提交、推送或分发时执行对应检查；普通编辑先检查改动内容，不因此自动启动全仓历史审计或版本收尾。检查通过不授予提交、推送、发布或修改线上凭据的权限。

### 检查什么

- 凭据：API key、Token、Cookie、密码、私钥、带认证信息的 URL/连接串，以及实际可用的测试凭据。
- 个人与环境信息：未获准公开的姓名、邮箱、电话、账号/群号、用户内容，真实部署的内外网 IP、私有域名、主机名、绝对路径中的用户名、NAS 挂载和共享路径。覆盖源码、注释、文档、配置、夹具、文件名、日志、数据库和备份。
- 非文本内容：截图中的地址栏、侧栏、底部状态栏、账号、路径和通知，以及图片 EXIF/注释等元数据；压缩包、安装包、source map、CI artifact 和镜像也可能带入上述信息。
- 区分真实敏感值与正常示例。`localhost`、保留示例地址、通用路径和明确的合成夹具可以保留；按用户既有公开意图保留公开仓库地址、公开署名和许可证归属。不能为了“无个人信息”删掉必要署名，也不能把真实凭据列为允许项。

### 提交前

1. 确认目标仓库、分支和提交范围；只读查看工作区与暂存文件清单，保留无关改动。检查拟提交的文件名、提交说明和作者邮箱是否包含不应公开的信息。
2. 扫描**暂存区的实际内容**，不能只检查工作区文件。首次采用规则或缺少有效基线时，补查全部已跟踪文件；`.gitignore` 不能排除已跟踪内容。文本用本地密钥扫描加个人信息/IP/路径定向搜索，二进制与截图另行检查，不能靠文本搜索判定通过。
3. 用环境变量、仓库外配置、相对或通用示例路径替换敏感值；真实用户数据换成合成样本。截图裁掉无关区域或用不透明遮盖，并清除敏感元数据；重新打开最终图片核对，改成 JPG 或降低画质不等于脱敏。
4. 只重新暂存已授权范围，复查实际暂存内容；暂存版本与已检查版本不同就重新检查。当前文件干净不代表历史干净，已经进过提交的内容按推送前流程处理。

### 推送与分发前

1. 明确目标远端和**所有实际待推送的分支、标签及其提交范围**，包括自动跟随或批量推送的标签；不要输出含认证信息的远端 URL。用已核实的远端引用确定增量范围；首次推送、远端基线不明或已有检查证据不足时，检查拟推送引用的完整可达历史。
2. 检查每个候选引用的完整已跟踪文件树，并检查待推送历史中的文件版本、提交说明、作者信息和标签说明。新增后又删除的凭据仍会随中间提交发送；只看最终 diff、HEAD 或当前工作区不够。已有历史检查可以复用，但必须对应确定的提交和相同检查范围，新的提交、标签和产物仍需检查。
3. 有外发产物时检查**最终将上传的文件**，而不只检查源码。核对打包清单、构建上下文与忽略规则，检查归档/安装包内容、source map、图片元数据、CI artifact，以及镜像的配置、构建历史和各层；后续层删除的敏感文件仍可能留在前层。未跟踪或已忽略文件也可能被打包。
4. 记录检查对应的候选 SHA、引用范围和产物校验值，以及工具、人工检查、结果和未覆盖项。只对已检查范围表述“未发现敏感信息”；扫描失败、范围不完整、二进制未检查或疑点未处理不能写成通过。外发前内容有变动，重查受影响范围。

### 历史清理是硬性要求

- 发现敏感信息曾进入 Git 历史，必须清除受污染的历史版本，包括提交内容、提交说明、作者/提交者邮箱和标签说明；不能只修当前文件或新增一个删除提交，也不能以“已经提交/推送过”为由保留。按需改写或删除受影响提交，保留有效变更和必要署名；旧的受污染提交不得继续从项目发布引用访问。
- 清理范围覆盖所有受影响分支、标签、远端和镜像，包含本地备份引用、reflog 及残留对象。先在仓库外隔离准备可回退副本并限制访问；完成验证后清理本次副本和旧对象，不能把含敏感信息的备份分支、Git bundle 或扫描报告一并上传。
- 使用当前已有授权执行历史清理；本次任务已明确要求清理历史时，不为同一步骤重复确认。缺少必要的改写/覆盖远端授权时，先完成安全准备并请求具体授权；受污染历史不得因此被继续提交、推送或分发。
- 覆盖远端前核对分叉、其他协作者和精确旧 SHA，使用绑定该 SHA 的 `--force-with-lease` 或等效保护；远端变化就停止覆盖并重新审阅，不用无保护强推绕过。通知协作者按授权执行，避免旧克隆把受污染历史重新推回。
- 清理后重新扫描完整可达历史、候选文件树和实际产物，核对每个受影响远端的引用与干净候选 SHA 一致。配置后续提交使用获准公开的身份或 noreply 邮箱，防止个人邮箱重新进入历史。
- 已分发的包、CI artifact、平台隐藏引用和缓存按实际泄露范围一并处理。托管平台缓存或他人克隆不能靠本地改写保证清除；明确遗留范围并执行获授权的平台清理流程，未核实不能声称“所有副本已删除”。有效凭据还必须撤销或轮换，历史清理不能代替失效处理。平台处理边界见 [GitHub 清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

### 工具、发现与处理

- 优先使用本地可用的密钥扫描器和有界搜索；配置脱敏输出，先给出文件名、位置、类别和数量，必要时连路径也脱敏。扫描器没有覆盖到的个人信息、IP、路径和图片仍需检查，不能只靠扫描器的默认规则。缺少工具时用本地搜索和人工审阅补齐；无法覆盖的内容明确标记未检查。
- 不把仓库、截图或命中内容上传到外部扫描/识图服务；不在终端输出、对话、PR 或永久报告中回显敏感原文。临时扫描报告放在仓库外且限制访问，结束后清理；允许项只记录必要的公开用途，不抄录真实秘密。
- 发现真实敏感信息时，先完成已授权的本地修复；涉及历史的必须执行上述历史清理并复查，再继续受影响的提交、推送或分发。撤销或轮换凭据按具体范围和已有授权执行，缺少授权才请求该项授权。不要顺手删除本地私有配置或生产数据。
- 已推送或分发的有效凭据按泄露处理：明确报告轮换/撤销和历史清理需求；只删源码不能使旧凭据失效。未完成的处置如实列为阻塞，不宣称绝对没有泄露或整个项目已经安全。

## 备份与恢复

先列出需要保护的资产：数据库、用户文件、运行状态、配置、密钥、报告和交付归档。构建产物和可重新生成缓存通常不需要备份。

| 数据面 | 最低备份要求 |
| --- | --- |
| D0 可重建 | 可不备份；记录重新生成方式 |
| D1 需备份 | 定期备份；至少一份不在故障设备/卷上；验证可读取 |
| D2 强一致/多写 | 定期一致性备份；迁移前备份；保留回滚窗口；定期恢复演练 |

每个 D1/D2 项目至少写清：

- 备份什么、放在哪里、多久一次、保留几份；
- 可接受的最长数据丢失时间和恢复时间；
- 恢复命令或操作步骤；
- 谁可以执行恢复，恢复前需要什么确认；
- 密钥和配置文件如何恢复。

迁移前先验证备份能读取；备份失败时停止迁移。不要用覆盖唯一备份的方式测试恢复。恢复演练使用临时目录或副本，验证后再接触真实数据。

## 事故处理

先控制影响，再定位原因。常见场景：

| 场景 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 数据库损坏或迁移失败 | 停止写入；保留现场；验证最近备份；隔离恢复 | 直接重建数据库、覆盖唯一备份 |
| Token/密钥泄露 | 撤销或轮换；检查使用记录；限制入口 | 只删日志、继续使用旧密钥 |
| 部署失败/服务不可用 | 停止继续发布；查看健康与日志；回滚应用；核对数据 | 在故障环境反复重试 |
| 磁盘满/资源耗尽 | 找到增长源；清理可再生缓存；扩容或限流 | 删除用户数据和历史报告 |
| 权限/越权事件 | 关闭入口；保留下审计；轮换凭据；通知受影响者 | 静默修改权限后当作没发生 |

通用顺序：**停止扩散 → 保留证据 → 判断影响范围 → 恢复或轮换 → 验证关键路径 → 记录后续项**。事故记录放在仓库外或临时 work 目录；只有可复用的处理结论才提炼进运维文档。

## 监控与告警

只监控会促使行动的信号：

- 服务存活/就绪失败；
- 磁盘、内存或队列积压超过阈值；
- 备份失败或长时间未成功；
- TLS 证书即将过期；
- 关键同步/任务连续失败；
- 认证异常或公开入口被错误暴露。

单人项目可以用邮件、QQ 或 NAS 通知，不需要 Prometheus/Grafana 全家桶。告警要能指向下一步操作；没有处理动作的指标不告警。日志有保留上限，避免磁盘被日志吃满。

## 依赖与供应链

- 使用 lockfile；基础镜像和 CI 工具固定版本。
- 依赖更新与功能改动分开；安全修复可以单独提前。
- 定期检查安全公告、废弃依赖、许可证和不维护的包。
- 模型权重、字体、图标和素材记录来源与分发限制；非商业许可不能随商业分发。
- 运行镜像只装生产依赖；不在镜像中保留测试、源码、缓存和密钥。

## 环境与晋级

- 本地、开发、预发布和生产使用不同配置；真实密钥不跨环境复用。
- 测试和预发布使用可丢弃数据；生产数据不直接作为测试夹具。
- 晋级顺序是同一产物从检查到验收再到部署；不要在每个环境重新构建不同版本。
- main 自动部署的项目，合 main 就是生产变更；人工验收和部署授权必须在合并前完成。

## 桌面分发（简版）

- 本地自用工具只需版本和校验值，不强制代码签名、自动更新或企业级供应链体系。
- 对外分发时尽量签名并发布 SHA-256；暂时无法签名就明确提示 SmartScreen 和未知发布者。
- Tauri/Electron 不把 CSP 设为 null；限制远程内容，校验 sidecar、更新包和外部路径，不执行任意 shell。
- 只有真实存在自动更新、商业分发或敏感权限时，才增加更新签名、回滚通道和更细的权限隔离。

## 数据迁移（简版）

- 单机单用户项目允许维护窗口：备份 → 停服 → 迁移 → 启动；失败时恢复备份或回滚应用。
- 持续服务或多写数据库：先加向后兼容的 schema，再部署兼容应用，确认旧结构无消费者后再删除；不需要零停机时不做复杂编排。
- 破坏性迁移单独确认，备份必须可验证，并在可丢弃数据库上演练；不要自动回滚数据库。

## 退役与清理

项目或服务停止时：

1. 停止入口和定时任务；
2. 撤销 Token、Webhook、CI Secret、DNS 和端口映射；
3. 备份或按确认删除数据、卷和报告；
4. 移除容器、镜像、临时证书和旧 artifact；
5. 更新 README/运维说明，标记 frozen 或已退役；
6. 在项目索引中记录归档位置和恢复条件。

删除数据、卷和远端资源需要单独确认；不能把“停服务”当成“删数据”的授权。

## 当前校准

- reYunPlex：NAS 单机、SQLite 和媒体文件；重点是备份、Plex 路径权限、证书/反代和部署回滚。
- AVNDB：Postgres、Redis、worker 和多用户内容；重点是数据库备份、队列积压、worker 内存、迁移回滚和密钥轮换。
- lirating：SQLite、报告和 QQ 群数据；重点是群号/昵称隐私、报告保留、插件配置和真实群验收。
- DiscordManager：JSON 状态、Discord 权限和 Bot Token；重点是状态备份、Token 轮换、单实例锁和 Discord 结构变更。
- SceneVault：SQLite、用户截图、NAS 归档和 Windows 分发；重点是恢复演练、Windows 安装/升级、模型许可和 NAS 断线。
- gsg：Postgres/Redis 与自动部署；重点是生产凭据隔离、数据库迁移顺序和双仓库部署收敛。

安全、备份和恢复是 D1/D2 项目的持续责任，不是版本收尾才想起来的一次性任务。
