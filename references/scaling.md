# 规模升级与降级

“规模变大”不是一个词。至少分成六个轴：代码、协作、运行、数据、交付和依赖。每个轴独立升级、独立降级，不合成项目等级。

## 六个规模轴

| 轴 | 小规模默认 | 升级触发 | 升级后新增 |
| --- | --- | --- | --- |
| 代码 | 单文件、单模块 | 多模块、多包、高变更频率的大文件 | 模块边界、导入方向、路径别名、按包检查、文件规模预算 |
| 协作 | 个人维护 | 第二个维护者、公开贡献 | PR 审查、保护 main、共享配置、提交和分支约定 |
| 运行 | 本地、单进程 | 常驻服务、多环境、多部署目标、长线运营 | CI、环境配置、健康检查、回滚、日志、性能预算 |
| 数据 | 可重建、单写者 | 需保留、多写者、跨进程访问 | 备份恢复、迁移演练、事务约束、SQLite/Postgres 判断 |
| 交付 | 无交付、本地使用 | 服务器部署、安装包、插件市场、公开镜像 | 版本单一来源、标签、产物校验、实机验收、发布授权、包体积预算 |
| 依赖 | 少量标准库或现有依赖 | 依赖增多、多个包共享 | 依赖准入、许可证/安全检查、锁文件、升级节奏 |

## 升级触发器

- 单文件超过 800 行，触发职责检查；超过 1500 行，需要拆分计划或保留理由；超过 2000 行，默认不再新增功能，除非是生成物、数据表、单一算法或无法自然分割的测试。
- 一个文件被频繁修改、缺陷集中或每次改动都牵动多个区域，比“绝对行数最大”更值得先拆。
- 出现多个包或多个独立发布单元，才建立共享类型、导入方向和按包检查；单包项目不提前做 workspace 治理。
- 出现第二个维护者或公开贡献，才需要 PR 审查、保护 main、CODEOWNERS 和更正式的提交约定。
- 出现服务器部署或多环境，才需要完整 CI、健康检查、回滚、环境隔离和运行日志。
- 出现不可重建数据或多写者，才升级到更严格的备份、迁移和数据库约束。
- 出现外部分发，才需要版本标签、安装包/镜像、校验值和真实环境验收。
- 依赖明显增多时，才建立许可证检查、安全更新和统一升级节奏。

升级按轴进行，不要求一次全部发生。一个项目可以代码规模很大、协作仍是个人、运行仍是单机；这时只需要模块边界和文件预算，不需要 PR 流程或服务拆分。

运行进入长线运营后，再补性能预算和容量测试；交付开始产生镜像/安装包后，再限制构建次数、镜像层数和产物保留策略。性能与 CI 的具体指标见 references/performance-and-ci.md。

## 降级条件

- 一次性脚本：不需要 CI、测试体系、版本发布和模块拆分；保留运行入口、样本数据和错误输出即可。
- 单文件小工具：main-only，formatter 可选；不要为了 1700 行强行拆分，只有当它持续演进、频繁修改或承担多个职责时才拆。
- 本地静态页面：静态托管即可，不需要后端、数据库或容器。
- 单用户本地工具：不需要 RBAC、邀请、双令牌和多租户。
- 单写者本地数据：SQLite 或 JSON 足够，不需要 Postgres、Redis 或队列。
- 无外部分发：不需要发布标签、安装包或镜像发布流程；需要分享时再补。
- 已冷冻项目：不升级依赖、不迁移、不加功能，只保留运行、备份和恢复路径。

降级不是删除历史。已有迁移、兼容和发布路径只有在确认没有消费者后才能移除。

## 文件规模与拆分

行数是烟雾报警器，不是拆分目标。判断一个文件是否需要拆，先看它有几个独立变更原因：

- 同时做请求、状态、业务规则、文件 I/O 和布局：值得拆。
- 只是一个复杂算法或完整数据表：可能保持原样。
- 生成代码、构建产物、锁文件、测试夹具：不计入日常文件预算。
- 测试文件：按行为组织；除非编辑困难，不优先为行数拆。
- CSS：按设计令牌、基础、布局、组件、报告区块拆；单个报告样式完整而稳定时可以保留。

拆分时按职责，不按行数平均切割：

- Vue 页面：页面壳、容器状态、展示组件、composable、API 客户端、纯格式化逻辑分开；保持状态所有权清晰。
- Rust 服务：按用例、状态机、文件 I/O、归档、恢复和外部进程边界拆；共享类型单独放。
- Python 模块：按 application、domain、persistence、report 等职责拆；避免循环导入。
- CSS：先抽设计令牌和复用布局，再按组件或报告区块拆；不要为每条规则建文件。

重构是行为保持任务，单独提交；一次只拆一个边界，完成后检查类型、构建和受影响路径。不要在一次功能改动里顺手拆多个大文件。

## 运行时性能

拆分源码不会直接让运行时变快。应用慢时先 profile 数据量、算法、渲染、I/O 和网络；文件行数不是性能指标。大文件可能拖慢类型检查、编辑器索引和构建，但这与线上运行速度是两件事。

## 当前校准

- SceneVault：采集/归档 Rust 服务和 Capture/Workbench 页面是优先拆分候选，按发现、分类、归档、恢复边界拆。
- AVNDB：WorkCompletionCenter、角色详情页面和作品完成服务是优先候选，按运行编排、步骤执行、重试/查询、展示状态拆。
- lirating：report.css、main.py、application.py 属于中等优先级；先按报告区块和应用层职责整理。
- reYunPlex、gsg、DiscordManager：当前源码大多低于 800 行，没有大文件危机，不为了统一规范强行拆。
- music-audit：scan.mjs 是单文件工具；继续演进或频繁修改时再拆，一次性使用不必动。

这些判断会随项目变化；重新评估时看当前文件、变更频率和职责，不照抄旧结论。
