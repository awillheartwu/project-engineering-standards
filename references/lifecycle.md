# 生命周期、分支与交付边界

## 先区分三个概念

| 概念 | 含义 | 主要要求 |
| --- | --- | --- |
| 部署 | 把服务安装或更新到运行环境，持续提供服务 | 健康检查、备份、回滚、运行版本核对 |
| 分发 | 构建安装包、插件包或镜像并交给使用者安装 | 版本、产物完整性、干净环境验收、校验值 |
| 交付 | 部署与分发的统称 | 分支、版本、验收和授权边界 |

桌面应用通常属于分发，不属于服务器部署；插件市场、安装包和静态站点也属于分发。数据重要但只在本机使用、没有交付物的项目，不因为数据重要就必须使用 dev/main；它需要的是备份、迁移前检查和恢复验证。

## 分支模型

分支模型由交付风险和维护协作决定，不由项目规模或数据库类型决定。

| 情形 | 默认分支 | 日常工作 | 收尾与交付 |
| --- | --- | --- | --- |
| 个人本地工具，无部署、无分发 | main | 直接提交；做类型、构建或静态检查 | 需要分享时再打标签 |
| 有正式交付：服务器部署、桌面安装包、插件市场、公开镜像 | dev + main | 日常在 dev；大改开 codex/<主题> | 版本收尾与实机验收后，main 只快进；标签指向最终 main |
| 多人协作或公开贡献 | dev + main | 功能分支 + 审查；保护 main | 通过审查后快进 main；发布另按授权 |
| 已冷冻 | 保留原分支 | 不新增功能、不升级依赖 | 只维护运行、备份和恢复路径 |

统一规则：

- main 始终可运行、可交付；不能把未验收的版本直接推上去。
- 禁止强推覆盖他人提交；远端分叉先合并审阅。
- 分支名表达目的；大改使用 codex/<主题> 或团队约定的前缀。
- 数据关键但不交付的项目，可以继续 main-only，但必须有备份和恢复；数据关键且有交付时，才进入 dev + main。

## 生命周期

### 日常开发

- 确认改动范围和受影响的数据、配置、交付物。
- 只做与改动相关的类型、编译、格式和静态检查；不为每个改动自动新增测试。
- 保留工作区中与任务无关的修改；提交前查看状态和暂存差异。
- 涉及真实数据的操作先说明影响和恢复方式。

### 版本收尾

只有用户明确要求当前版本进入“版本收尾”才启动测试阶段。收尾至少包含：

1. 冻结范围，核对需求、差异、已知缺陷和未完成项。
2. 备份需要保留的数据；迁移前验证备份和回退路径。
3. 整理测试，只保留行为契约、数据保护、权限边界、失败恢复和已确认缺陷。
4. 运行项目约定的完整检查；失败时区分本次变更、环境问题和既有缺陷。
5. 更新使用说明、版本来源和变更记录。
6. 在干净环境构建交付物；需要实机验收的，单独记录。
7. 分别报告本地、CI、部署、分发和真实环境的结果；不要互相替代。

### 发布与部署

- 发布标签指向最终 main 提交；标签创建后不移动。
- 部署前确认目标环境、当前版本、备份和回滚方式。
- 部署后核对运行版本、健康状态和关键只读行为。
- CI 绿灯不是部署成功；部署成功也不是真实环境验收完成。
- 发布、部署、分发分别按用户授权执行；版本收尾本身不授予这些动作。

### 冷冻

- 标记 frozen 后不继续加功能或升级依赖，除非出现安全修复或明确恢复请求。
- 保留可运行产物、运行说明、备份和恢复路径。
- 恢复 active 前重新填写定位卡，评估依赖、数据迁移和交付责任。

## 授权边界

| 动作 | 是否可由当前任务自动覆盖 | 说明 |
| --- | --- | --- |
| 读取、分析、本地修改 | 通常在任务范围内 | 不碰无关修改和生产数据 |
| 提交 | 用户明确要求时 | 只暂存授权范围内的改动 |
| 推送 | 单独授权 | 一个远端成功、另一个失败时只补失败端 |
| 部署 | 单独授权 | 说明目标、版本和回滚方式 |
| 发布/标签 | 单独授权 | 标签指向最终 main，不移动 |
| 分发/上架 | 单独授权 | 验证产物、校验值和可见性 |

讨论、计划、检查、版本收尾都不等于发布授权。一次明确授权可以覆盖连续且范围不变的步骤；出现新的外部副作用时重新确认。

## SceneVault 的归类

SceneVault 是 Windows 本地优先桌面应用，不是服务器部署项目：

- 交付方式是构建安装包并分发，用户可以离线使用。
- 有正式版本和 Windows 安装包，所以适用 dev + main。
- 数据在本机 SQLite 和用户目录；备份、迁移前检查、恢复和 Windows 实机验收属于数据责任。
- WSL 中能访问源码，不等于 Windows 安装、升级、NAS 共享和恢复已经验收。
- 发布标签、安装包构建、真实安装和分发是不同层，分别记录。

因此它属于“有正式交付”的分支模型，但不属于“服务器部署”。这两件事不能混用。
